<decisions>
## Implementation Decisions

### Locked Field-Report Findings
- P0 issues are mandatory: brief delivery, unsafe `--resume-last --worktree-auto`
  behavior, and brief examples/skill wording must be corrected.
- P1 issues are mandatory where source changes are feasible in this phase:
  branch-aware pipeline diff summaries, missing criteria visibility, stage vs.
  final verdict clarity, better schema error details, first-run git guidance,
  event/artifact path discoverability, and canonical merge/iterate guidance.
- P2 issues should be addressed through docs/help/event vocabulary unless they
  require large new feature work.

### the agent's Discretion
- Prefer small source-level fixes with tests over broad rewrites.
- Keep existing public command names stable unless rejecting a dangerous flag
  combination is required.
- Source files remain the authority; generated `skill/` and `plugin/` outputs
  must be refreshed with `npm run build`.

</decisions>

<specifics>
## Specific Ideas

- Append rendered brief content to the actual worker prompt under a distinct
  heading, then assert prompt preview / captured request includes brief fields.
- Reject `--resume-last --worktree-auto` with a clear error pointing users to
  `iterate <task_id>` or a fresh worktree task.
- Return schema validation `details` and `suggestion` for invalid briefs.
- Let `captureGitDiff` accept a base ref so pipeline terminal summaries can
  report committed branch work relative to the task base.
- Include missing completion criteria in pipeline NDJSON/status payloads and
  human events.
- Update docs so the recommended path is task -> Monitor -> result/check ->
  adversarial review/verdict -> bridge merge, not manual git merge.

</specifics>

<deferred>
## Deferred Ideas

- Full native Agent intercept redesign is out of scope unless needed for docs

</deferred>
