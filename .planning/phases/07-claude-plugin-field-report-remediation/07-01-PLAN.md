# Phase 7.1: Runtime Contract Fixes - Plan

## Goal

Fix the runtime behaviors that made the field session unreliable: brief delivery,
unsafe resume/worktree semantics, schema-error opacity, and misleading pipeline
completion summaries.

## Tasks

1. Deliver brief contents to Codex worker prompts.
   - Update task dispatch prompt construction so `--brief` appends rendered
     `brief.md` content to the worker prompt before config footer injection.
   - Keep the registry artifacts unchanged.
   - Add tests proving `worker_assignment`, `specific_concerns`, and
     `acceptance_criteria` reach the effective prompt.

2. Reject unsafe resume/worktree combinations.
   - Add validation that refuses `--resume` or `--resume-last` when
     `--worktree-auto` is also present.
   - Error message must say this is thread-only resume and recommend
     `iterate <task_id>` or a fresh task.
   - Update hook/user-prompt guidance that currently suggests `--resume-last`.

3. Improve brief validation errors.
   - Preserve `loadBrief(...).details` on `CliError`.
   - Add a useful suggestion for schema violations.
   - Test JSON envelope includes `error.details` for unknown fields.

4. Make pipeline diff summaries branch-aware.
   - Extend `captureGitDiff` to accept an optional base ref.
   - For auto-pipeline final summaries, use task `base_sha`/`base_ref` when
     `jobId` has registry metadata.
   - Keep existing dirty-worktree behavior for non-task or no-base flows.

5. Surface missing completion criteria.
   - Add missing item text to `[PIPELINE:check:done]` detail or attached block.
   - Ensure `PIPELINE_COMPLETE` NDJSON and returned pipeline result include the
     list.
