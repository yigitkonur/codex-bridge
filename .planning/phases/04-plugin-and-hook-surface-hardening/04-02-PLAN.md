# 04-02 Plan: Version Canonicality Metadata And Distribution Stance

## Objective

Make version and canonicality relationships explicit and tested across `package.json`, root plugin metadata, packaged plugin metadata, marketplace metadata, legacy skill metadata, and packaged plugin skill metadata.

## Tasks

1. Choose the source-backed Phase 4 stance: the packaged marketplace plugin remains a noncanonical alpha channel unless metadata is fully promoted.
2. Update `esbuild.config.mjs` comments/labels so they match that stance.
3. Strengthen tests so package version, root plugin version, legacy skill version, packaged skill version, packaged alpha plugin version, and marketplace entry are checked together.
4. Add baseline/static metadata checks so future version drift fails in `npm run verify:static`.
5. Run focused metadata tests and baseline contracts.

## Acceptance Criteria

- There is no contradiction between build comments, marketplace metadata, package metadata, and tests.
- Packaged plugin alpha version is explicitly related to package version.
- Root canonical plugin metadata and legacy skill metadata stay aligned to `package.json`.
- Packaged skill metadata is explicitly aligned to the runtime package version.
