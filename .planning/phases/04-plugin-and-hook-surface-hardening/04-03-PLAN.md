# 04-03 Plan: Stop Gate Monitor And Hook Spoof-Resistance

## Objective

Make hook behavior deliberate and spoof-resistant: Stop hook activation must stay lock/setup gated, monitor hints must be sanitized wherever emitted, and generated hook registration must match what is actually shipped.

## Tasks

1. Preserve Stop hook lock/setup gating and timeout margin tests.
2. Decide whether staged hooks should be registered now; wire them if they are production-ready, or remove/quarantine false surfaces if not.
3. Reuse monitor command validation in `pre-tool-agent.mjs` before emitting Monitor payloads from bridge stdout.
4. Replace skipped spoofed-stdout tests with active negative cases for malformed JSON, `ok:false`, wrong command, completed state, job mismatch, shell metacharacters, unknown argv, and prefix/suffix noise.
5. Add focused negative tests for SubagentStop same-session spoof risks where practical.
6. Run hook-focused tests and full static verification.

## Acceptance Criteria

- Hook manifest registration matches shipped behavior.
- Unsafe Monitor command text cannot be emitted from PostToolUse or PreToolUse hook paths.
- Arbitrary stdout cannot cause hook additionalContext unless it is a valid, expected bridge envelope and job-scoped monitor hint.
- Stop hook still blocks only when the project lock and setup state prove the review gate is active.
