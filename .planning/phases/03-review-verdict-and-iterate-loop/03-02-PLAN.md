# 03-02: Auto-pipeline partial-completion and check-stage proof

<objective>
Make auto-pipeline completion state fail closed and expose stage, budget, partial-completion, review, fix, and check outcomes explicitly enough that users can trust whether automation actually finished.
</objective>

<threat_model>
- False complete: invalid completion-check JSON is treated as successful completion.
- Hidden partials: failed or skipped stages do not tell users what completed and what remains.
- Budget ambiguity: users cannot tell whether stage timeout or total timeout stopped the run.
- Parser drift: auto-pipeline review parsing diverges from task-bound review parsing.
- Event mismatch: terminal events and JSON result disagree about failing stage.
</threat_model>
