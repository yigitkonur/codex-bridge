# 03-03: Verdict, approved-head merge, and iterate orchestration

<objective>
Complete the human-control loop: review writes a safe verdict payload, merge enforces the approved reviewed head, and `iterate` orchestrates task -> review -> verdict -> follow-up until approval or explicit incomplete state.
</objective>

<threat_model>
- Merge drift: a branch changes after review but still merges under an old approval.
- Verdict spoofing: arbitrary payloads mark unsafe work approved without branch-head evidence.
- Shell injection: review findings with quotes, backticks, or newlines become shell syntax.
- Infinite loop: `iterate` keeps launching follow-up tasks without respecting `--max`.
- Silent partial: task or review failure loses artifacts and returns a vague error.
- Contract drift: plugin docs still describe staged `iterate` after implementation.
</threat_model>

</action>

<task id="03-03-03" title="Implement iterate orchestration helper">
<read_first>
- `src/codex-bridge.mjs` `handleIterate`

- `src/lib/registry.mjs`
- `src/lib/review-result.mjs`
- `test/plugin-surfaces.test.mjs`
</read_first>
<action>
Replace staged `handleIterate` behavior with a real loop helper, for example `runIterateLoop(options)`.

Required behavior:

- prompt input starts an initial worktree-backed task with write enabled;
- task-id input resumes from existing registry metadata;
- each iteration waits for or reads task completion artifacts;
- each iteration runs adversarial review in task-bound mode;
- each iteration writes a verdict from normalized review output;
- approved verdict stops with `status: "approved"` and a structured merge next action;
- `needs-attention` or `must-fix` starts a follow-up task in the same worktree when iterations remain;
- iteration limit returns `status: "iteration-limit"` with artifacts preserved;
- task, review, verdict, and follow-up failures return explicit incomplete statuses and artifact pointers.

Use dependency injection or small pure helpers so tests can simulate task/review/verdict outcomes without live Codex.
</action>
<verify>
- Add `test/iterate-loop.test.mjs` for immediate approval, needs-attention then approval, must-fix then iteration limit, task failure, review failure, and verdict failure.
- Update plugin-surface test so it no longer expects `status: "not-yet-orchestrated"`.
</verify>
<acceptance_criteria>
- `rg "not-yet-orchestrated" src test scripts plugin` finds no runtime or test expectation except old changelog text if present.
- Iterate JSON result has `iterations[]` entries with `iteration`, `task_id`, `review_result`, `verdict`, `reviewed_branch_head_sha`, and optional `next_task_id`.
