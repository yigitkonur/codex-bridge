## Feature Dependencies

```text
Codex CLI/app-server readiness -> task/send/review/setup/auth-status/version
Config layering -> runtime options -> task/review/send behavior
State root -> job registry -> status/result/wait/events/cancel
Background task -> task-worker -> runBridgeTask -> session events -> Monitor
task --write + --worktree-auto -> worktree registry metadata -> review/verdict -> merge
Adversarial review -> review output schema -> renderReviewResult
auto_review/post_task_prompt -> runAutoPipeline -> [DONE]/[INCOMPLETE]/[ERROR]
Stop gate lock + setup readiness + transcript -> read-only task --no-pipeline -> ALLOW/BLOCK
v2 hook automation -> hooks.json registration -> hook-specific tests -> product claim
```

## Roadmap Implications

1. Preserve shipped baseline CLI behavior first: task execution, continuation controls, review, status/result/events/wait/cancel, setup/config/version/update, and stop-gate readiness.
2. Treat worktree/verdict/merge as the advanced shipped lane, but keep requirements tied to local fast-forward merge until PR/remote delivery is implemented.
3. Promote hook automation only after each latent hook is registered in packaged hook config and covered by non-skipped behavior tests.
4. Keep adapter language precise: "backend-ready architecture" is supported; "multiple production backends" is not supported today.
5. Make `iterate` a roadmap phase rather than table stakes, because the current command deliberately emits a manual next action.
