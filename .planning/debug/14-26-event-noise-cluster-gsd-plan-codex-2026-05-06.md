# Phase 1 — Analysis

## Case Map

| Focus case | Validity | Severity | Decision |
|---|---|---:|---|
| `14.26` event-noise cluster | Real, but not correctness-breaking. The stream is truthful; the defect is signal density at fan-out. | P2 | Fix with default filtering plus NDJSON compaction. Do not redesign the event stream. |

## Problem

The bridge writes and surfaces three classes of low-signal event data at task scale:

| Subcase | What the problem actually is | Is it real? |
|---|---|---|
| `[DIRECTIVES]` | Every task turn writes a one-line runtime-config echo. It is useful forensic data but redundant in the parent Monitor stream when many same-shaped jobs launch together. | Real for Monitor defaults. The event should still be written to `.events`; it should just be excluded by default. |
| `ITEM_COMPLETED reasoning text=null` | Reasoning items without surfaced text were persisted as separate `ITEM_COMPLETED` NDJSON records. Each record says only "a reasoning item happened" with no replayable payload. | Real. These records add countable activity but no transcript value. |
| `TURN_PARAMS developer_instructions` | `TURN_PARAMS` included the full collaboration-mode payload, including repeated plan/default developer instructions. Parallel plan-mode jobs repeat the same text into every NDJSON file. | Real, though the exact reported 6,463-byte size is version-specific and overstated for the current checkout. The architectural issue remains. |

## Root Cause

| Subcase | Root cause in current architecture |
|---|---|
| `[DIRECTIVES]` | `runBridgeTask` emits `formatDirectivesEvent()` at turn start to preserve effective runtime config. Monitor hints are generated by `buildMonitorHint()` through `formatTailCommand()` and `DEFAULT_MONITOR_EXCLUDE`; if `DIRECTIVES` is not in that list, every fan-out job surfaces startup metadata to the orchestrator. |
| `ITEM_COMPLETED reasoning text=null` | `extractItemText()` intentionally returns `null` for reasoning items without textual summaries, but the task/send item callbacks historically logged every completed item without checking whether the extracted text had replay value. |
| `TURN_PARAMS developer_instructions` | `buildCollaborationMode()` embeds developer instructions into `turnParams.collaborationMode.settings`; the turn-start log previously serialized that full object directly instead of replacing large stable instruction text with a content-addressed reference. |

## Blast Radius

| Who notices | Manifestation | When |
|---|---|---|
| Human/agent orchestrators | Monitor output is harder to scan; actionable `[QUESTION]`, `[PLAN]`, `[ERROR]`, `[DONE]`, and pipeline tags are surrounded by repeated setup noise. | Parallel background dispatches and verification waves. |
| NDJSON consumers | Session logs contain repeated empty reasoning records and large repeated instruction payloads. Queries and artifact diffs get larger without more evidence. | Any task/send turn, amplified by fan-out. |
| Forensic debugging | Risk only if compaction deletes reconstructable context. | After compaction, consumers must follow `developer_instructions_ref` for full prompt instructions. |

## Dependencies And Overlaps

| Overlap | Relationship |
|---|---|
| `24-P1-checkpoint-default-filter-mismatch.md` | Shares the default-filter surface. This plan does not derive new work from it; the checkout already also excludes verbose `CHECKPOINT` while keeping `CHECKPOINT_SUMMARY`. |
| Event JSON / Monitor follow behavior | Same `events` command, but terminal-tag semantics and JSON envelope shape are not part of 14.26. |
| NDJSON replay docs | Must be updated because `ITEM_COMPLETED` is no longer "every finalized item" and `TURN_PARAMS` can now reference a sidecar instruction file. |

# Phase 2 — GSD Implementation Plan

## Grouping

| Cluster | Cases | Fix surface | Contract fixed |
|---|---|---|---|
| Monitor default filter | `[DIRECTIVES]` | `src/lib/session-log.mjs`, `src/lib/envelope-helpers.mjs`, command/plugin docs | Default Monitor excludes runtime echo noise while `.events` still retains it for explicit opt-in. |
| NDJSON item aggregation | `ITEM_COMPLETED reasoning text=null` | `src/lib/task-runtime.mjs`, `src/handlers/task.mjs`, NDJSON docs | Empty reasoning completions are counted once per turn instead of logged as payload-free item records. |

## Risk And Rollback

| Risk | Impact | Rollback |
|---|---|---|
| Consumers expect `ITEM_COMPLETED` for every reasoning item | Low to medium for custom NDJSON queries; those records had no text. | Revert only the reasoning-null suppression and keep `reasoningStepsCount` additive. |
| Consumers treat `.ndjson` as self-contained and do not copy sidecar refs | Medium for archival tooling that needs exact developer instructions. | Emit full instructions once per session plus hash-only repeats instead of sidecar-only compaction. |
| Default filter surprises users who relied on visible `[DIRECTIVES]` | Low. Raw `.events` still has the block. | Run `events ... --exclude HEARTBEAT,CHECKPOINT` or no exclude to opt back in. |
| Shared default filter overlaps checkpoint work | Medium coordination risk with parallel agents. | Keep 14.26 acceptance specific to `DIRECTIVES`; do not claim checkpoint changes as part of this case. |

## Acceptance Criteria

| Subcase | One-line check |
|---|---|
| `[DIRECTIVES]` | Default Monitor command includes `--exclude HEARTBEAT,DIRECTIVES,CHECKPOINT`, and an events run with that exclude omits `[DIRECTIVES]` while `--exclude HEARTBEAT` still shows it. |
| `ITEM_COMPLETED reasoning text=null` | A fake task with two empty reasoning completions writes zero `ITEM_COMPLETED` reasoning/null records and writes `reasoningStepsCount: 2` on the turn terminal NDJSON record. |
| `TURN_PARAMS developer_instructions` | `TURN_PARAMS` contains `developer_instructions_hash`, `developer_instructions_length`, and `developer_instructions_ref`, contains no inline `developer_instructions`, and the referenced file contains the original instructions. |

## Out Of Scope

| Not addressed | Reason |
|---|---|
| Broad event architecture redesign from documents `00-13` or `15` | Scope is limited to the single focus file. |
| Checkpoint-summary/default-checkpoint policy beyond existing checkout behavior | Sibling case, not a 14.26 source-of-truth item. |
| Adding a new `--include` CLI flag | Existing `--exclude` already supports opt-in by using a narrower exclude list. |
| Changing terminal-tag semantics, `events --json` envelope shape, or wait/status behavior | Separate event-consumer contracts. |
| Reworking storage retention or log shipping | Volume reduction here is local to event records and Monitor defaults. |
